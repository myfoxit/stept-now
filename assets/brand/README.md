# Stept logo

Standard geometry, step right. Two offset bars on a 24×24 grid.

## Files

| File | Use |
|---|---|
| `stept-mark-partial.svg` | **Primary.** Light surfaces. Default everywhere you have room. |
| `stept-mark-partial-dark.svg` | Dark surfaces. Indigo lifted to `#6D66F0`. |
| `stept-mark-black.svg` | Single-colour fallback: print, embossing, partner logo walls. |
| `stept-mark-white.svg` | Single-colour reversed. |
| `stept-mark-indigo.svg` | Restricted — small solid contexts only. |
| `stept-mark-currentcolor.svg` | Inline in HTML; inherits `color` from the parent. |
| `stept-favicon.svg` | Browser tab. Optically corrected, not a scaled master. |
| `stept-app-icon.svg` | 512px maskable / apple-touch-icon. |
| `stept-lockup-horizontal.svg` | Mark + wordmark, light. |
| `stept-lockup-horizontal-dark.svg` | Mark + wordmark, dark. |

## Colour

```css
--stept-ink:          #14161A;  /* upper bar, wordmark, primary text */
--stept-indigo:       #4F46E5;  /* leading bar, accent */
--stept-indigo-dark:  #6D66F0;  /* indigo on dark surfaces only */
```

`#4F46E5` on `#14161A` is about 3.4:1 — enough for a logo, not enough for small UI. That is why the dark files ship a separate hex rather than a filter.

## Rules

**Clear space** — the height of one bar (7 units at 24px, so 7px at 24px, 21px at 72px) on all four sides. Nothing enters it, including the wordmark in an improvised lockup.

**Minimum size** — 20px for the mark, 88px wide for the lockup. Below 20px, switch to `stept-favicon.svg`; its bars are thicker and its gap is wider because the 24px master closes up at small sizes.

**Never** recolour the mark to arbitrary brand-adjacent hues, rotate it, add a container shape other than the supplied app icon, apply a shadow or gradient, stretch it non-uniformly, or place the light lockup on a mid-tone photo.

**Wordmark** — the lockups use live `<text>` with an Inter fallback. Convert to outlines in Figma or Illustrator before shipping so rendering does not depend on the viewer's fonts. If you keep Inter, the settings are 500 weight, -0.03em tracking.

## HTML

```html
<link rel="icon" href="/stept-favicon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="/stept-app-icon.svg">
```

For an inline mark that follows light and dark mode, use `stept-mark-currentcolor.svg` and set `color` on the wrapper — but note this gives you the mono mark, not the split. The split needs the two file variants.

# Using it in this repo

This directory is the source of truth. Nothing else in the repo redraws the
geometry: in-product marks are components that reproduce these rects, and every
raster is generated by `scripts/gen-brand-assets.mjs`. If the mark changes,
change it here and re-run that script — never hand-edit a PNG or a favicon.

## Which variant goes where

Three jobs, three answers. The deciding question is *what is the mark doing on
this surface* — not which file is prettiest.

**Mono ink — the default.** Wherever the mark is furniture standing next to a
word: the app sidebar and workspace switcher, the docs header, the extension
panel, the widget's "Powered by" line, the GitHub README. It is near-black on
light and white on dark, which in practice means `currentColor` inheriting the
surface's text colour. Most of the mark's appearances in the product are this.

**Split (ink + indigo) — where the logo is the subject.** The landing header,
the social card, the sign-in card. Three places, all of them a front door. The
indigo is what makes it a logo rather than an icon, so it is worth something
only where someone is actually looking at it.

**Solid indigo tile — small and out of our control.** Favicons, the
apple-touch icon, the Chrome toolbar icon. A transparent mono mark is invisible
on half the tab strips and toolbars in the world; a filled indigo tile is not.
This is the one context the kit permits a container shape, and the app icon is
the container.

## In-product marks read the surface's own indigo

`StepMark.tsx`, `Wordmark.astro` and the extension's `Logo()` reproduce this
geometry but paint the leading bar with the surface's existing indigo token
(`--brand`, `--primary`, `--accent`) rather than a hard-coded `#4F46E5`. That is
deliberate. Those tokens already lift indigo on dark surfaces exactly the way
the `-dark` files here do, so the mark inherits correct dark-mode contrast for
free and can never drift out of step with the buttons and links beside it.

Standalone asset files — favicon, app icon, social card, extension icons — have
no token to inherit, so they carry the literal hexes from the table above.

## Wordmarks are HTML text, not the lockup SVGs

`stept-lockup-horizontal*.svg` ship live `<text>`, so they are for hand-off
(press kits, partner logo walls, decks) after being outlined — not for the web
surfaces here. Every wordmark in the product is real HTML text set in the site's
own self-hosted display font, which is sharper, selectable, and one less font
dependency. Pair it with the mark; do not embed the lockup SVG.

## Regenerating

```
node scripts/gen-brand-assets.mjs
```

Writes `favicon-32.png` + `apple-touch-icon.png` into `landing/`, `frontend/`
and `docs-site/` public dirs, `og.png` into `landing/public`, and `16/48/128.png`
into `extension/src/public/icon`. The `.svg` favicons are copied from here
verbatim and are the ones browsers actually use; the PNGs are the fallback.
